# 결과 화면 결정 (확정)

> [[design-decisions]] 의 하위 페이지. 결과 화면(오버레이·카드·상세 시트·주문서·챗·사진 저장)에 관한 확정 결정. 바뀌면 이 페이지와 로그를 같이 갱신한다.
> 안내문 덮개·번호 판정과 정리 영역(요약·번역문·원문)의 규칙은 [[overlay-and-photo]] §안내문 덮개.

- **결과 화면 기본은 오버레이**(2026-10-23 변경, 이전엔 카드 기본 + 오버레이 BETA 배지). 탭 순서도 「오버레이 | 카드」, BETA 배지는 제거. 번역 완료 도장·공유 버튼·시간 표시는 제거.
- **대표 이미지는 「그림」(픽셀 아이콘 46종, [[icons]])**, 「사진」 토글은 비활성(준비 중). 이유: Wikimedia Commons 검색 품질이 낮음. 재개 조건은 [[backlog]].
- **상세 시트**: 발음 + 한 개 주문 문구(일본어 원문 「〜を ひとつ ください」, 한국어 원문 「〜 하나 주세요」·「인분」 항목은 「1인분 주세요」)와 그 발음·뜻. 원문과 앱 언어가 같으면 발음·뜻 줄은 숨긴다. 안내문 항목에는 가격·주문 문구를 숨긴다.
- **메뉴판 문구(notes)** 는 카드·오버레이 어디에도 그리지 않는다(2026-10-20 피드백 4차, 오버레이는 번호 배지만). 챗 맥락으로만 쓴다. 안내문·기타의 문단은 [[overlay-and-photo]] §안내문 덮개.
- **오버레이 「표시 끄기」 토글은 결과 화면 제목 줄 오른쪽**(2026-10-21): 사진 안에 두면 사진을 가리고(사용자 거부), 사진 위 전용 줄은 여백만 만든다. 사진 아래의 「두 손가락으로 확대…」 안내 문구는 삭제(설명 없이도 쓰는 동작).
  상태를 `ResultScreen` 이 들므로 카드↔오버레이를 오가도 끈 상태가 유지된다(사용자가 끈 것을 기억하는 쪽이 자연스럽다고 판단).
  처리 중 화면은 종류 판정 전엔 라멘 대신 로고(카메라) 아이콘 — 메뉴판을 전제하지 않는다.
- **오버레이 표시 방식**: 번호 배지가 기본. 이름·가격 칩은 4개 이하이고 회전 없는 사진에서만(2026-10-20). 메뉴판에서는 분류 제목·안내 문구를 사진 위에 덮지 않는다(어지럽다는 피드백). 파파고식 덮기는 안내문·기타에만. **2026-10-23 문단 덮개로 교체**(사용자 결정): 문단 단위 번역, 바탕은 샘플링 배경색 **불투명**, 상자에 화면 11px 이상으로 안 들어가는 문단은 **번호 배지 + 사진 아래 목록**(확대하면 들어가는 만큼 덮개로), 사진 아래 **요약 / 번역문 / 원문** 탭. 요약은 사진에 적힌 내용만, 사진에 없는 일반 상식은 「참고 · 사진에 없는 일반 정보」로 구분해 사용자가 규칙으로 착각하지 않게. 덮개·번역문 줄은 누르면 선택, 다시 누르면 해제(원문·번역 시트는 삭제). 판정 기준 상세는 [[overlay-and-photo]] 「안내문 덮개」. 「N줄 번역 · 일본어만」 부제는 계속 없음.
- **오버레이 배지 크기**: 한 크기(20px), 붐빌 때만 13px 까지 축소. 이웃이 멀다고 키우지 않는다.
- **카드 묶음**(2026-10-21): 분류(안주·식사·음료) 대신 메뉴판 섹션으로 묶는다. 1단계 항목마다 모델이 `group`(섹션 제목을 옮기거나 즉석에서 지은 2~6자)을 붙이고, 항목 8개 이상인 메뉴판은 서버가 2단계와 병렬로 묶음 정리 호출(`groups` 이벤트, 4~8개)을 돌려 묶음별 호출의 이름 흔들림(차/티, 핫샌드/샌드위치)을 합친다. 정리 결과가 없으면 항목 group(2~10개·60% 이상일 때) → category 순으로 폴백. 전체 보기는 섹션 헤더, 칩을 고르면 그 묶음만.
- **카드 배지**(2026-10-21): 태그 줄은 카드 본문에서 뺀다. 고르는 데 도움이 되는 배지(매움 > 날것 > 선택 필요 > 인기)만 그림 아래 최대 2개(`.chip--mini`). 음료·튀김·채식 같은 분류성 태그는 상세 시트에만. 스테퍼는 카드 오른쪽 아래(본문 열을 stretch 해 바닥에 붙임). 배치 시안 A·B·C 중 사용자가 A 변형을 선택.
- **주문서**(2026-10-20): 메뉴판에서만. 수량은 카드 오른쪽 아래 스테퍼(0이면 + 만), 하단 고정 바는 먹색 바탕에 주홍 그림자(토스 주문서 느낌), 주문 문구는 LLM 없이 템플릿(すみません、注文お願いします。… 以上です。 + 한글 발음 + 뜻). 「크게 보여주기」는 일본어만 전체 화면.
- **주문서는 묶음 전체가 하나**(2026-10-23): 여러 장 묶음에서 1번 사진에서 담은 것과 2번 사진에서 담은 것이 한 주문서(바의 개수·합계, 시트 목록, 주문 문구)로 합쳐진다. 이전엔 사진마다 따로라 사진을 바꾸면 담은 것이 사라져 보였다. 시트 줄에는 묶음일 때만 「사진 N」(띠 번호와 같음) 배지. 항목 id(「묶음:순번」)는 사진마다 겹치므로 수량은 `사진 id → 항목 id → 수량`(`BatchOrder`)으로 들고, 저장은 사진별 localStorage 키 그대로(옛 저장 값 호환, 지우기 정리 불변). 결과 화면은 묶음 단위(App 의 key 가 첫 사진 id)로 살아 있고, **보기 방식(오버레이/카드)·표시 토글은 App 이 들어** 읽는 중·실패 사진(처리 중 화면)을 거쳐 돌아와도 유지된다(홈으로 나가면 처음으로). 사진에 딸린 선택·챗 팝업은 사진을 바꿀 때 닫고, 하위 뷰의 확대·필터·안내문 탭은 `key={scan.id}` 로 사진마다 새로 시작한다. 메뉴판 사진이 하나라도 있으면 안내문 사진을 보는 동안에도 바는 남는다.
- **주문 문구 상황 3종**(2026-10-21): 첫 주문(すみません、注文お願いします … 以上です) · 추가 주문(追加で注文お願いします …) · 항목만(목록 + お願いします). 추가 주문마다 같은 인사를 붙이면 어색해서 시트 안 세그먼트로 고른다. 기본은 첫 주문.
- **한국어 메뉴판 주문서**(2026-11-01, PR #67): 주문 문구는 사진 원문 언어로 만든다. 한국어 원문은 「저기요, 주문할게요. / 이름 하나·둘…열(11 이상 N개, 이름에 「인분」이 있으면 N인분) / 이상이요.」, 추가 주문은 「저기요, 추가 주문할게요.」, 항목만은 「… 주세요.」. 「N인분」은 이름의 N 에 수량을 곱해 센다(「부대찌개 (2인분)」 1개 → 2인분). 말할 때 인분 토막만 떼고 크기 같은 다른 괄호(「파전(대)」)는 직원이 읽어야 하니 둔다. 가타카나 발음은 보여주는 글 그대로를 서버와 같은 규칙(`api/_lib/hangulToKana.ts`)으로 옮기고(조립은 `src/lib/orderText.ts` 순수 함수, `scripts/bench/order_test.ts`), 뜻 줄은 사진의 번역 언어 사전(`order.frames`, 앱 언어를 바꾼 뒤 연 기록도 섞이지 않게). 일본어 원문 문구·한글 발음은 그대로. 「크게 보여주기」·복사(버튼 이름은 원문 언어)는 원문. 원문과 앱 언어가 같으면 발음·뜻 줄 없음. 한 묶음에 원문 언어가 다른 메뉴판이 섞이면 첫 메뉴판과 같은 언어의 사진만 주문서에 들어간다(문구 한 언어·합계 한 통화).
- **메뉴판 챗**(2026-10-21 → 2026-10-22 시트로): 카드·오버레이 공통 **우측 하단 말풍선(`bubble`) 버튼** → **화면 아래에 붙는 시트**(주문서 바가 있어도 그 위에 덮는다 — 배경막이 바를 가리므로 띄울 이유가 없고 입력칸이 키보드 바로 위에 와야 한다). 열려 있는 동안 말풍선 버튼은 숨기고 닫기는 시트 우상단 ✕ 하나(버튼이 ✕ 로 바뀌며 아래를 차지하던 방식은 입력칸과 키보드 사이가 벌어져 폐기). 추천 질문 칩은 자리만 차지한다는 피드백으로 삭제(2026-10-22 낮에 넣었던 맞춤 질문·↻ 섞기도 같이 삭제, `chatTitle` 은 `lib/kind.ts` 로). 제목·버튼 라벨은 종류별 「메뉴판에 / 안내문에 / 사진에 물어보기」. 서버 프롬프트도 종류별 안내문(`chatSystem(kind)`)으로 나뉘어 안내문·기타 사진에서 메뉴판을 전제하지 않는다. 카드 상세가 열린 채 버튼을 누르면 그 항목이 「지금 보는: ○○」 맥락 칩으로 붙는다. 답 밑에 「글자만 보고 답함 / 사진을 다시 봤어요」와 참조 항목 칩(최대 4, 누르면 카드 상세). 팝업은 닫아도 숨기기만 해 답이 끊기지 않고, 닫힌 뒤 온 답은 버튼 배지. 대화는 스캔별 localStorage 20개. 마스코트는 라멘이 아니라 말풍선(사용자 결정: 라멘은 처리 중 화면과 겹쳐 챗으로 안 읽힘). `bubble` 은 화면 전용 아이콘이라 「글자 없음」 화풍 규칙의 예외로 「?」 를 넣었다(메뉴 매칭·모델 선택 경로에는 없음). 카드 상세가 열린 동안 버튼은 숨기고 시트 안 「물어보기」 버튼이 그 항목을 맥락으로 연다.
  **버튼 위치**(2026-10-23): 주문서 바가 있으면 바가 잰 실제 높이(ResizeObserver, `useLayoutEffect`) 위 12px. 상수 84px 로 두었을 때 바(≈83px)와 1px 차이라 글꼴 행간이 다른 Safari 에서 겹쳤다.
  **사진은 필요할 때만**: 항목·문구 JSON 으로 먼저 묻고(≈3s), 질문에 「놓친·빠진·사진·작은 글·위치·색」이 있으면 처음부터 사진을 붙인다(≈9s). 그 밖에 모델이 `[사진 필요]` 라고 하면 사진을 붙여 한 번 더(≈13s).
  **여러 장 묶음은 챗 하나**(2026-10-23): 맥락은 묶음 사진 전부의 항목·글줄(항목 키 「사진번호-묶음:순번」, 글줄에 사진 번호 `p`, 시스템 프롬프트에 묶음 안내 추가). 사진이 필요하면 모델이 `[사진 필요: n]` 으로 볼 사진을 지정하고 클라이언트는 그 장만 붙여 다시 묻는다(질문에 「사진」류 말이 있으면 지금 보는 사진을 먼저 붙이고, 모델이 다른 장을 지정하면 그 장을 한 번 더 → 질문당 최대 2장, 비용 상한). 대화는 묶음에 하나(키는 챗을 처음 열 때 **완료된 첫 사진** id. 실패한 사진은 기록에 안 남아 그 키면 다시 열 때 사라진다. 불러올 땐 묶음 사진 전부의 키를 합쳐 사진별로 저장하던 옛 대화도 이어받음)이고 사진을 바꿔도 열어 둔 답이 끊기지 않는다(읽는 중·실패 사진을 골라 처리 중 화면으로 가면 끊김 표시, 이전과 같음). 저장하는 참조는 모델 키(묶음 안 번호)가 아니라 **「사진 id/항목 id」**(실패 사진이 빠져 번호가 당겨져도 안 어긋남, 옛 접두 없는 참조는 그 대화를 저장했던 사진으로 변환). 참조 칩은 다른 사진의 항목이면 「○○ · 사진 2」로 표시하고 누르면 그 사진으로 바꾸며 상세를 연다. 답 밑 표시는 「사진 2를 다시 봤어요」. 질문에 「2번 사진」처럼 번호가 있으면 그 장을 먼저 붙이고, 번호만 부르는 말은 사진 힌트로 치지 않는다. 항목·글줄 상한(200·120)은 묶음 전체 예산을 **사진별 균등**으로 나눈다(서버·클라이언트 같은 규칙, 앞에서부터 자르면 뒤 사진이 통째로 빠짐). 버려진 안: 카드 안 말풍선(항목 질문만 됨), 질문=필터(설명형 질문 약함), 라멘 마스코트 시트.
- **챗 키보드**(2026-10-22): 질문을 보내면 입력칸 포커스를 빼 모바일 키보드를 내린다(키보드가 답을 가려 닫았다 다시 열어야 했다는 피드백).
- **사진 저장**: 웹은 갤러리에 직접 쓸 수 없다 → 결과 화면 저장 버튼이 공유 시트로 원본 파일을 넘긴다. 자동 저장은 불가로 확정.
