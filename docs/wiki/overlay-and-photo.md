# 화면 좌표·회전·라벨 규칙

## 좌표

- 모든 좌표는 **원본 사진을 0~1000 으로 정규화**한 값. 항목 bbox = 그 항목 `word_ids` 의 OCR 단어 상자 **합집합**(`src/lib/scan.ts unionBox`). 이미지 폴백 모드에서만 모델이 준 bbox 를 쓴다(정확도 낮음).
- 역사: 처음엔 Claude 가 이미지에서 bbox 를 직접 추정했는데 반 칸~수십 px 씩 어긋났다(모델 한계) → OCR 단어 상자로 전환해 해결.

## 사진 세우기 (`src/components/MenuPhoto.tsx`)

1. EXIF 방향: `<img>` → canvas 경로가 모든 최신 브라우저에서 적용(createImageBitmap 의 imageOrientation 은 Safari 신뢰 불가).
2. 글자 방향 `rotation`(0/90/180/270): OCR 단어 vertices[0]→[1] 방향의 중앙값을 90° 로 반올림(`api/_lib/ocr.ts`). 세로쓰기 일본어는 글자가 서 있어 0°.
3. 미세 기울기 `tilt`: 위 중앙값에서 90° 배수를 뺀 나머지. ±15° 이내만 되돌린다.
4. 글자 영역 확대: 단어 상자 합집합 + 8% 여백(`focusBox`)이 상자에 꽉 차도록 CSS transform 하나로 회전·확대·중앙 정렬. 원근 왜곡은 펴지 않는다.
5. 마커는 사진과 같은 레이어에 % 로 두고, `markerScale = 1/(fit.scale × zoom)` 을 곱해 화면 크기를 일정하게 유지한다.

## 마커 선택 규칙 (`src/screens/OverlayView.tsx`)

| 대상 | 표현 |
|---|---|
| 메뉴 항목 ≤10개 | 이름·가격 칩. 세로쓰기면 3단으로 엇갈려 배치 |
| 메뉴 항목 >10개 | 번호 배지(13~26px, 이웃 항목과의 화면 거리 ×0.85) + 사진 아래 번호 목록 |
| notes(제목·안내문구), 비메뉴 사진의 문장 | **덮어쓰기 라벨**: 원문 bbox 크기 그대로 종이색 상자 + 한글. 글자 크기 = min(굵기×0.78, 길이×0.94/글자폭em, 28), 9px 미만이면 두 줄 |
| 두 줄로도 안 들어가는 긴 문구 | 위치에 `※n` 마커만, 본문은 사진 아래 목록 (판정은 폭 350px 기준으로 마커·목록이 같은 번호를 쓰도록 통일) |

글자 폭 추정: CJK 1em, 그 외 0.55em (`textEm`).

## 터치

- 페이지 줌은 끔(`user-scalable=no`) → 상세 시트가 확대된 채 뜨지 않는다.
- 확대 전 `touch-action: pan-y`: 한 손가락은 페이지 스크롤, 두 손가락만 사진 확대(최대 4×). 확대 중 `none`: 한 손가락이 사진을 끈다. 두 번 탭 또는 「원래대로」 버튼으로 복귀.
- React 의 touch 리스너는 passive 라 `preventDefault` 가 듣지 않는다 — 제어는 전부 `touch-action` 으로.
- 「표시 끄기」 토글(결과 화면 제목 줄 오른쪽, `ResultScreen` 이 상태를 들고 `showMarks` 로 내려줌)로 모든 마커를 숨긴다. 사진 아래 조작 안내 문구는 없다(2026-10-21 삭제).

## 실기기 확인이 남은 것

핀치·끌기·공유 시트는 헤드리스로 재현 불가. 변경 후에는 사용자 확인을 요청한다.

## 덮개 라벨 (2026-10-20 파파고식 → 2026-10-21 획만 지우기)

- 글자색은 상자 안에서 배경과 가장 먼 픽셀 평균, 배경색은 상자 바깥 띠의 중앙값. 테두리 없음(`src/lib/sample.ts`, `OverlayView` 의 `CoverLabel`).
- **덮는 층은 단색이 아니라 배경 조각**(`patchBox`): 원문 bbox(+여유)를 잘라 ① 배경색과 먼 픽셀을 획으로 판정하고 5px 팽창(안티앨리어싱·JPEG 링잉까지) ② 획 픽셀만 상하좌우 가장 가까운 비획 픽셀로 거리 가중 보간 ③ 획 자리만 5×5 평균. 획이 아닌 픽셀은 그대로라 종이 질감·조명 그라데이션·얼룩이 이어진다. 조각 5개에 30~40ms(결과 화면이 뜬 뒤 비동기, 체감 지연 없음). 대비가 낮거나 획이 없으면 null → 단색으로 복귀.
- 번역이 두 줄로 접힐 상자(`willWrap`, 폭 350px 기준)는 굵기 방향 여유를 1.2배로 잘라 접힌 글도 조각 위에 놓는다. 그래도 모자라면 단색 상자.
- 조사한 대안: ML 인페인팅(Google Lens 가 2022년부터 Magic Eraser 계열로 원문을 지움)은 기기에서 돌리기엔 무겁고 레이턴시가 늘어 제외. 색 상자 + 테두리 픽셀 군집(파파고·특허 US11568631 류)이 종전 방식. OpenCV inpaint + 획 마스크 팽창(StrokeNet)을 픽셀 연산으로 흉내 낸 것이 현재 방식.
- 사진 층이 `rotation + tilt` 만큼 돌아가 있으므로 라벨은 번호 배지처럼 역회전한다. `rotation` 이 90·270 이면 화면 기준 가로·세로가 바뀌므로 그 기준으로 세로쓰기(`vertical-rl`, 글자 바로 세움)를 정한다.
- 안내문(`kind !== 'menu'`)은 글줄 단위 notes 를 항상 제자리에 덮고 ※ 목록을 쓰지 않는다. 일본어 줄만 번역하고 영어·한국어·중국어 줄은 건드리지 않는다.
