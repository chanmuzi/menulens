## 작업 원칙

- **빨리 보여줄 수 있는 것은 빨리 보여준다**(2026-10-23 사용자). 결과를 모두 모았다가 한 번에 띄우지 않는다. 먼저 완성된 조각(메뉴 항목, 안내문 문단)으로 화면을 바로 열고, 늦게 오는 정보(설명, 묶음 정리, 요약)는 도착하는 대로 그 자리를 채운다. 비어 있는 자리는 「~쓰는 중」으로 표시한다.
  - 판단 기준은 **처음 무언가가 보이는 시점**과 **핵심 결과(번역)가 다 보이는 시점**이다. 부가 정보의 도착 시점을 맞추려고 핵심 결과를 늦추지 않는다.
  - 부가 정보를 위한 호출을 추가할 때는 그 호출이 핵심 결과의 표시를 막지 않는지 실측으로 확인한다. 예: 안내문 요약은 번역 뒤 따로 호출해 2~3.5초 늦게 오지만 덮개·번역문은 그 전에 다 보이므로 그대로 둔다(같은 시점에 받을 필요 없음).
  - 적용 사례: 메뉴 항목 스트리밍(`item`), 2단계 설명·묶음 정리 병렬(`details`·`groups`), 안내문 문단 스트리밍(`note`)과 요약(`summary`). [[architecture]] [[benchmarks]]

## 공통 (확정)

- **시안 A 「和紙」** (2026-10-19): 생성리 종이 `#F4EBD9`, 먹 `#2A211B`, 주홍 `#C8402F`. 2px 먹 테두리 + 오프셋 그림자(픽셀 게임 대화창), 도장·短冊 모티프.
  폰트: DotGothic16(픽셀, 일본어/라틴), Shippori Mincho(요리명), IBM Plex Sans KR(본문). 시안 B 「提灯」(다크)는 폐기.
- **앱 언어**(2026-10-31, 역방향 1차): 홈 오른쪽 위 버튼 「日本語 → 한국어」/「한국어 → 日本語」로 한국어·일본어 UI 를 바꾼다(기본은 기기 언어, 기기별 기억). 앱 언어 = 번역 대상 언어이고 사진 원문 언어는 자동 판정(다음 PR). 문구는 `src/i18n` 사전, 저장 데이터의 한국어 값(분류·태그)은 그대로 두고 표시만 바꾼다. 일본어 모드 문구는 「한국을 여행하는 일본인」 기준으로 쓴다.
- **역방향 분석**(2026-10-31, PR #66): 사진 원문 언어는 서버가 OCR 문자 체계로 자동 판정하고 번역 대상은 앱 언어. 가격 통화는 원문 언어를 따르고(원화 메뉴판은 ₩, 환산은 ≈ ¥) 환율은 JPY 기준 하나로 양방향 계산. **발음은 모델이 짓지 않는다**(사용자 요구: 틀린 발음을 알아채지 못한 적이 있음): 일본어 원문은 모델이 낸 히라가나 읽기를 규칙으로 한글로 옮기고(가나가 아니면 비운다), 한국어 원문은 이름을 규칙으로 가타카나로 옮긴다. 규칙은 `scripts/bench/rules_test.ts` 로 고정. 한국어 메뉴판의 주문서·한 개 주문 문구는 PR #67([[decisions-result]]), 챗 답변 언어는 PR #68(대화 기준 사진의 번역 언어 `lang.dst` 로 답한다 — 항목 이름 `tr` 이 그 언어라서, 스캔 뒤 앱 언어를 바꾸면 답은 옛 언어·UI 는 새 언어가 된다. 사진 번호·사진 힌트 말은 일본어도 알아듣고, 프로토콜 표시 `[사진 필요]`·`참조:` 는 한국어가 기준이되 일본어 표기도 방어), 통역 자리 바꿈은 PR #69([[decisions-talk]] §역방향, 통역 발음도 규칙으로).
- **언어 규칙**: 메뉴판에서 읽은 데이터(요리명·가게명)는 원어 위, 앱 언어 아래. 앱 UI(버튼·상태·필터·태그·제목)는 **앱 언어만**(2026-10-31 전까지는 한글만). 장식용 일본어(「めにゅーれんず」, 「最近」, 제목 아래 히라가나 `KIND_SUB`, 「豆知識」, 「えらー」)는 2026-10-22 전부 제거(사용자: 한글만 있어도 되는 요소는 걷어내기). 남긴 일본어는 뜻이 있는 것뿐: 헤더의 언어 버튼, 원문 데이터.
- **아이콘 선택**: 원문 키워드(豚·鶏·牛·海老 …) → 모델 선택 → 별칭 → 카테고리 기본(접시). 안내문 항목은 항상 접시. 소혀 등 고기 부위는 `meat`.
  **음료는 음료 규칙만**(2026-10-21): 음료 칸이거나 모델이 음료 아이콘을 골랐으면 음식 규칙을 아예 보지 않는다(アイス = 차가운, ソーダ割 = 소다로 탄 소주, オレ = 오레 ≠ オレンジ). 커피 외 음료를 녹차잔 하나로 뭉뚱그리지 않도록 `wine`·`cup`(타피오카·밀크티·스무디)·`mug`(코코아·우유)를 추가했고, 빵류도 `sandwich`·`hotdog` 로 나눴다.
  전수 조사는 `scripts/bench/icon_audit.mjs`(진단 저장소 스캔 294건 기준 62건 교정). 모델이 낸 `飲料`·`食事` 같은 원문 분류명은 `scan.ts` 에서 한국어 다섯 값으로 되돌린다.
- **아이콘**(2026-10-20): 매칭 → 없으면 로고 자리표시 → 상위 모델이 격자 생성 → 캐시 교체. 이미지 생성 모델은 쓰지 않고 텍스트 격자(팔레트 고정)로 화풍을 유지한다. 자주 나오는 생성 아이콘은 `pixel-icon` 스킬 절차로 정식 스프라이트로 승격.
- **가격 표기**(2026-10-20): 메뉴판에 세전(세후)가 같이 있으면 그대로 `¥380 (¥418)`. 원화·합계는 실제 지불액(세후). 목록·배지에서 가격 없는 항목은 빈칸.

## 폐기·보류

- Opus 5.5 이미지 직접 분석(느림, bbox 부정확) → OCR 2단으로 대체.
- Document Parse(항목별 좌표 없음) → OCR 로 대체.
- Upstash REST 캐시 코드 → `REDIS_URL` TCP 로 대체(사용자가 Redis Cloud 를 만들었기 때문).
- 그 밖의 폐기 이력(분석 전 확인 화면, 앱 안 자체 카메라, 덮개 반투명 상자·배경 조각 등)은 각 결정 항목 안에 「(이전: …)」으로 남아 있다.
