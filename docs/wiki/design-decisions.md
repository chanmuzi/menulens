# 디자인·UX 결정 (확정 / 폐기)

> 바꾸려면 사용자 결정이 필요하다. 바뀌면 이 페이지와 로그를 같이 갱신한다.

## 확정

- **시안 A 「和紙」** (2026-10-19): 생성리 종이 `#F4EBD9`, 먹 `#2A211B`, 주홍 `#C8402F`. 2px 먹 테두리 + 오프셋 그림자(픽셀 게임 대화창), 도장·短冊 모티프.
  폰트: DotGothic16(픽셀, 일본어/라틴), Shippori Mincho(요리명), IBM Plex Sans KR(본문). 시안 B 「提灯」(다크)는 폐기.
- **언어 규칙**: 메뉴판에서 읽은 데이터(요리명·가게명)는 원어 위, 한글 아래. 앱 UI(버튼·상태·필터·태그·제목)는 **한글만**. 장식용 일본어(「めにゅーれんず」, 「最近」, 제목 아래 히라가나 `KIND_SUB`, 「豆知識」, 「えらー」)는 2026-10-22 전부 제거(사용자: 한글만 있어도 되는 요소는 걷어내기). 남긴 일본어는 뜻이 있는 것뿐: 헤더의 「日本語 → 한국어」 배지, 원문 데이터.
- **결과 화면 기본은 카드**, 오버레이는 BETA 배지(탭 바깥 우상단, 탭 폭 균형 유지). 번역 완료 도장·공유 버튼·시간 표시는 제거.
- **대표 이미지는 「그림」(픽셀 아이콘 33종)**, 「사진」 토글은 비활성(준비 중). 이유: Wikimedia Commons 검색 품질이 낮음. 재개 조건은 [[backlog]].
- **아이콘 선택**: 원문 키워드(豚·鶏·牛·海老 …) → 모델 선택 → 별칭 → 카테고리 기본(접시). 안내문 항목은 항상 접시. 소혀 등 고기 부위는 `meat`.
  **음료는 음료 규칙만**(2026-10-21): 음료 칸이거나 모델이 음료 아이콘을 골랐으면 음식 규칙을 아예 보지 않는다(アイス = 차가운, ソーダ割 = 소다로 탄 소주, オレ = 오레 ≠ オレンジ). 커피 외 음료를 녹차잔 하나로 뭉뚱그리지 않도록 `wine`·`cup`(타피오카·밀크티·스무디)·`mug`(코코아·우유)를 추가했고, 빵류도 `sandwich`·`hotdog` 로 나눴다.
  전수 조사는 `scripts/bench/icon_audit.mjs`(진단 저장소 스캔 294건 기준 62건 교정). 모델이 낸 `飲料`·`食事` 같은 원문 분류명은 `scan.ts` 에서 한국어 다섯 값으로 되돌린다.
- **처리 중 화면**: 스캔 라인·찾는 대로 붙는 칩·8칸 픽셀 게이지·라멘 김·「기다리는 동안 한 가지」 상식(豆知識 라벨은 2026-10-22 제거). 「먼저 찾은 것부터 보기」 유지.
  **종류에 맞는 문구**(2026-10-21): 판정 전에는 「읽는 중 / 무슨 글인지 보고 묶는 중」처럼 메뉴판·안내문 어느 쪽도 전제하지 않고, 서버의 `kind` 이벤트가 오면 「메뉴판 읽는 중 · 메뉴 n개 찾았어요」 / 「안내문 읽는 중 · 줄마다 번역하는 중」(카메라 아이콘, 표기 상식 豆知識)으로 바뀐다. 결과·기록 화면의 종류 이름은 `src/lib/kind.ts` 한곳(메뉴판 / 안내문 / 사진 속 글자).
- **홈 문구**(2026-10-21 → 2026-10-22): 제목 「메뉴판이나 안내문을 찍으면 바로 읽어드려요」만 남기고 부제·프레임 안내 문구는 삭제(불필요하다는 피드백). 프레임 안은 설명 대신 **메뉴판 모형**(나무판 위 종이, 글줄 막대, 스캔 라인, 한 줄이 「라멘 ¥900」 칩으로 뜬 모습)으로 사진이 찍혀 번역된다는 것을 암시한다. 안내·오류 문구(붙여넣기 실패, 드롭 안내)는 그 위에 필요할 때만 뜬다. 앱 이름·로고·「앨범에서 / 촬영 / 붙여넣기」는 그대로.
- **상세 시트**: 발음(한글) + 「〜を ひとつ ください」 문구와 그 발음. 안내문 항목에는 가격·주문 문구를 숨긴다.
- **메뉴판 문구(notes)** 는 카드 뷰에 넣지 않고 오버레이에서만(덮어쓰기 라벨 또는 ※목록).
- **오버레이 「표시 끄기」 토글은 결과 화면 제목 줄 오른쪽**(2026-10-21): 사진 안에 두면 사진을 가리고(사용자 거부), 사진 위 전용 줄은 여백만 만든다. 사진 아래의 「두 손가락으로 확대…」 안내 문구는 삭제(설명 없이도 쓰는 동작).
  상태를 `ResultScreen` 이 들므로 카드↔오버레이를 오가도 끈 상태가 유지된다(사용자가 끈 것을 기억하는 쪽이 자연스럽다고 판단).
  처리 중 화면은 종류 판정 전엔 라멘 대신 로고(카메라) 아이콘 — 메뉴판을 전제하지 않는다.
- **기록 보관**: 건수 제한 없음(IndexedDB). 앱 차원의 자동 삭제 없음. 사용자가 개별·전체 삭제. 보관 정책 문구는 전체 기록 화면 맨 아래 한 문단(기기에만 저장, iOS Safari 7일 미사용 시 삭제 가능). 「홈 화면에 추가」 안내는 한 줄 접힘형, 닫으면 다시 안 보임(localStorage 플래그).
- **중단 확인과 비용**(2026-10-22): 읽는 중(OCR·LLM 호출이 열린 상태)에 「홈으로」를 누르면 `LeaveDialog` 가 「사진 N장을 아직 읽는 중이에요 / 설명을 아직 쓰는 중이에요」로 묻고, 중단하면 스캔별 AbortController 가 요청을 끊는다. 서버 `/api/analyze` 는 `req.signal` 을 OCR·1단계·2단계·묶음 정리 fetch 에 모두 넘겨 클라이언트가 끊으면 상류 호출도 끊고 진단 저장도 건너뛴다(`/api/chat` 과 같은 방식). **단, Vercel 은 `vercel.json` 의 `supportsCancellation: true` 가 있어야 끊김을 `req.signal` 로 전달한다**(기본은 꺼짐, 함수 자체가 종료됨) — 배포 설정이라 별도 PR 로 사용자 확인 후 merge. 로컬 개발 브리지(`vite-plugin-dev-api.ts`)는 `res.close` 를 signal 로 잇는다. 모음 화면의 미리 읽기는 묻지 않고 끊는다. 브라우저 뒤로가기·탭 닫기는 연결 자체가 끊겨 같은 효과. 기록에서 연 묶음은 다 끝난 상태라 묻지 않는다.
- **챗 키보드**(2026-10-22): 질문을 보내면 입력칸 포커스를 빼 모바일 키보드를 내린다(키보드가 답을 가려 닫았다 다시 열어야 했다는 피드백).
- **사진 저장**: 웹은 갤러리에 직접 쓸 수 없다 → 결과 화면 저장 버튼이 공유 시트로 원본 파일을 넘긴다. 자동 저장은 불가로 확정.

## 폐기·보류

- Opus 5.5 이미지 직접 분석(느림, bbox 부정확) → OCR 2단으로 대체.
- Document Parse(항목별 좌표 없음) → OCR 로 대체.
- Upstash REST 캐시 코드 → `REDIS_URL` TCP 로 대체(사용자가 Redis Cloud 를 만들었기 때문).
- **분석 전 확인 단계**: 모든 경로가 모음 화면을 거친다(2026-10-22). 한 장짜리 「이 사진으로 할까요?」 확인 화면은 모음 화면에 흡수됐고 확인 화면 컴포넌트는 자르기 전용 `CropScreen` 이 됐다. (이전: 앨범·붙여넣기·드롭은 확인 화면, 촬영은 바로 분석.) 크롭 핸들은 항상 보이고 기본은 전체(2026-10-20, 버튼으로 켜는 방식은 「사각형이 있는데 조정이 안 된다」는 피드백으로 폐기). 사각형만, 원근 보정 없음.
- **iOS 홈 화면 앱 상단 blur**: iOS 26 Liquid Glass 가장자리 효과(시스템이 그림, CSS 로 못 끔). WebKit 은 맨 위를 덮는 fixed·단색·전체폭·10px 초과의 **실제 요소**가 있으면 효과를 건너뛰고 그 색을 쓴다 → `index.html` 의 `.edge-top`(standalone 에서만 safe-top+44px, 종이색). 상태바 스타일 메타는 두지 않는다. 홈 앱은 Safari 에서 새로고침 후 재설치해야 반영(설치 시 페이지를 캐시).
- **iOS 붙여넣기 폴백**: 홈 화면 앱에서 `clipboard.read()` 가 막히면 「길게 눌러 붙여넣기」 상자를 띄워 네이티브 메뉴의 paste 이벤트로 받는다.
- **오버레이 표시 방식**: 번호 배지가 기본. 이름·가격 칩은 4개 이하이고 회전 없는 사진에서만(2026-10-20). 메뉴판에서는 분류 제목·안내 문구를 사진 위에 덮지 않는다(어지럽다는 피드백). 파파고식 덮기는 안내문·기타에만. **2026-10-23 문단 덮개로 교체**(사용자 결정): 문단 단위 번역, 바탕은 샘플링 배경색 **불투명**, 상자에 화면 11px 이상으로 안 들어가는 문단은 **번호 배지 + 사진 아래 목록**(확대하면 들어가는 만큼 덮개로), 사진 아래 **요약 / 번역문 / 원문** 탭. 요약은 사진에 적힌 내용만, 사진에 없는 일반 상식은 「참고 · 사진에 없는 일반 정보」로 구분해 사용자가 규칙으로 착각하지 않게. 덮개·번역문 줄은 누르면 선택, 다시 누르면 해제(원문·번역 시트는 삭제). 판정 기준 상세는 [[overlay-and-photo]] 「안내문 덮개」. 「N줄 번역 · 일본어만」 부제는 계속 없음.
- **여러 장 한 번에**(2026-10-21): 앨범에서 여러 장(최대 6)을 고르면 모음 화면(썸네일·더 찍기·앨범 추가·빼기·순서) → 사진마다 독립 스트림을 동시에(최대 3) 열고 **첫 장이 끝나는 대로 결과 화면**. 처리 중·결과 화면 위 썸네일 띠(썸네일마다 번호, 완료 ✓·읽는 중 …·실패 ✕, 띠 오른쪽 끝에 k/n — 「사진 2/2」를 앞에 둔 배치는 어색하다는 피드백으로 2026-10-22 변경)로 사진별 뷰를 오간다. 스캔은 한 장씩 따로 저장(`batchId` 공유)하고, **홈·전체 기록에서는 한 묶음이 한 줄**(「사진 N장 · 12개 메뉴」, 아이콘에 장수 배지, 지우기는 묶음 전체)이며 열면 같은 묶음이 띠에 오른다(2026-10-22, 각각 따로 뜨던 것을 묶음). 결과 화면 저장 버튼은 묶음 사진 전부를 한 번에 공유 시트로 넘긴다(폴백 새 탭은 첫 장만 열고 그렇다고 알린다). 붙여넣기·드롭도 모음 화면으로(2026-10-22, 한 장이어도 더 찍기·앨범 추가·자르기가 가능하게. PC 앨범 한 장일 때 추가 경로가 없다는 피드백). 영역 지정은 모음 화면에서 사진마다(아래 「사진별 자르기」).
- **메뉴판 챗**(2026-10-21 → 2026-10-22 시트로): 카드·오버레이 공통 **우측 하단 말풍선(`bubble`) 버튼** → **화면 아래에 붙는 시트**(주문서 바가 있어도 그 위에 덮는다 — 배경막이 바를 가리므로 띄울 이유가 없고 입력칸이 키보드 바로 위에 와야 한다). 열려 있는 동안 말풍선 버튼은 숨기고 닫기는 시트 우상단 ✕ 하나(버튼이 ✕ 로 바뀌며 아래를 차지하던 방식은 입력칸과 키보드 사이가 벌어져 폐기). 추천 질문 칩은 자리만 차지한다는 피드백으로 삭제(2026-10-22 낮에 넣었던 맞춤 질문·↻ 섞기도 같이 삭제, `chatTitle` 은 `lib/kind.ts` 로). 제목·버튼 라벨은 종류별 「메뉴판에 / 안내문에 / 사진에 물어보기」. 서버 프롬프트도 종류별 안내문(`chatSystem(kind)`)으로 나뉘어 안내문·기타 사진에서 메뉴판을 전제하지 않는다. 카드 상세가 열린 채 버튼을 누르면 그 항목이 「지금 보는: ○○」 맥락 칩으로 붙는다. 답 밑에 「글자만 보고 답함 / 사진을 다시 봤어요」와 참조 항목 칩(최대 4, 누르면 카드 상세). 팝업은 닫아도 숨기기만 해 답이 끊기지 않고, 닫힌 뒤 온 답은 버튼 배지. 대화는 스캔별 localStorage 20개. 마스코트는 라멘이 아니라 말풍선(사용자 결정: 라멘은 처리 중 화면과 겹쳐 챗으로 안 읽힘). `bubble` 은 화면 전용 아이콘이라 「글자 없음」 화풍 규칙의 예외로 「?」 를 넣었다(메뉴 매칭·모델 선택 경로에는 없음). 카드 상세가 열린 동안 버튼은 숨기고 시트 안 「물어보기」 버튼이 그 항목을 맥락으로 연다.
  **사진은 필요할 때만**: 항목·문구 JSON 으로 먼저 묻고(≈3s), 질문에 「놓친·빠진·사진·작은 글·위치·색」이 있으면 처음부터 사진을 붙인다(≈9s). 그 밖에 모델이 `[사진 필요]` 라고 하면 사진을 붙여 한 번 더(≈13s). 버려진 안: 카드 안 말풍선(항목 질문만 됨), 질문=필터(설명형 질문 약함), 라멘 마스코트 시트.
- **촬영도 여러 장, OS 카메라 왕복으로**(2026-10-21): 「촬영」은 한 장 찍으면 바로 분석하지 않고 **모음 화면**으로 간다(더 찍기 · 앨범에서 추가 · 빼기 ✕ · 순서 ◀▶ · 자르기 · 「N장 분석하기」). 카메라 입력은 한 번에 한 장만 돌려주므로 여러 장은 「더 찍기」로 OS 카메라를 다시 여는 왕복이다. 한 장 사용자의 탭 하나는 모음 화면에 있는 동안 **첫 장을 뒤에서 미리 읽기 시작**해 상쇄한다(이자카야 사진: 확인 후 13.5s → 8.9s, 모음 화면에 4s 머문 경우). 처리 중·결과 화면의 사진 띠 끝에도 「+ 더 찍기」가 있어 결과를 보면서 사진을 붙인다(한 장짜리도 띠를 보여 진입점이 되게, 묶음 id 가 없으면 승격해 저장. 기록에서 연 묶음에는 붙이지 않는다). 확정 전 미리 읽기 결과는 기록에 저장하지 않는다. 기록에서 묶음을 열면 찍은 순서(createdAt)로 띠에 올린다.
  **사진별 자르기**(2026-10-22): 모음 화면의 타일(사진 또는 「자르기」)을 누르면 그 한 장만 영역 지정 화면(「그대로 쓰기 / 이 영역만 쓰기」)으로 갔다가 모음으로 돌아온다. 한 장일 때만 있던 「영역을 지정해서 읽기」 버튼은 이 흐름으로 흡수. 「더 찍기」와 「앨범에서 추가」는 같은 크기의 점선 타일 둘(앨범 추가가 작은 글자 버튼이라 안 보인다는 피드백). 「메뉴판이 여러 면이면 읽는 순서대로…」 설명 문단은 삭제. 미리 읽던 사진은 자르기 화면에 들어가도 계속 읽고, 실제로 잘라 파일이 바뀐 경우에만 잘린 사진으로 다시 읽는다(그대로 쓰기·취소는 비용 없이 이어 감).
  **앱 안 자체 카메라(getUserMedia)는 하지 않는다**: 영상 스트림 프레임 캡처라 HDR·여러 프레임 합성·손떨림 보정·탭 초점·플래시가 빠져 어두운 가게에서 기본 카메라보다 불리하다. 왕복이 거슬리면 재검토(사용자 결정: 애플 카메라 화질 우선).
- **카드 묶음**(2026-10-21): 분류(안주·식사·음료) 대신 메뉴판 섹션으로 묶는다. 1단계 항목마다 모델이 `group`(섹션 제목을 옮기거나 즉석에서 지은 2~6자)을 붙이고, 항목 8개 이상인 메뉴판은 서버가 2단계와 병렬로 묶음 정리 호출(`groups` 이벤트, 4~8개)을 돌려 묶음별 호출의 이름 흔들림(차/티, 핫샌드/샌드위치)을 합친다. 정리 결과가 없으면 항목 group(2~10개·60% 이상일 때) → category 순으로 폴백. 전체 보기는 섹션 헤더, 칩을 고르면 그 묶음만.
- **카드 배지**(2026-10-21): 태그 줄은 카드 본문에서 뺀다. 고르는 데 도움이 되는 배지(매움 > 날것 > 선택 필요 > 인기)만 그림 아래 최대 2개(`.chip--mini`). 음료·튀김·채식 같은 분류성 태그는 상세 시트에만. 스테퍼는 카드 오른쪽 아래(본문 열을 stretch 해 바닥에 붙임). 배치 시안 A·B·C 중 사용자가 A 변형을 선택.
- **주문 문구 상황 3종**(2026-10-21): 첫 주문(すみません、注文お願いします … 以上です) · 추가 주문(追加で注文お願いします …) · 항목만(목록 + お願いします). 추가 주문마다 같은 인사를 붙이면 어색해서 시트 안 세그먼트로 고른다. 기본은 첫 주문.
- **주문서**(2026-10-20): 메뉴판에서만. 수량은 카드 오른쪽 아래 스테퍼(0이면 + 만), 하단 고정 바는 먹색 바탕에 주홍 그림자(토스 주문서 느낌), 주문 문구는 LLM 없이 템플릿(すみません、注文お願いします。… 以上です。 + 한글 발음 + 뜻). 「크게 보여주기」는 일본어만 전체 화면.
- **아이콘**(2026-10-20): 매칭 → 없으면 로고 자리표시 → 상위 모델이 격자 생성 → 캐시 교체. 이미지 생성 모델은 쓰지 않고 텍스트 격자(팔레트 고정)로 화풍을 유지한다. 자주 나오는 생성 아이콘은 `pixel-icon` 스킬 절차로 정식 스프라이트로 승격.
- **가격 표기**(2026-10-20): 메뉴판에 세전(세후)가 같이 있으면 그대로 `¥380 (¥418)`. 원화·합계는 실제 지불액(세후). 목록·배지에서 가격 없는 항목은 빈칸.
- **오버레이 배지 크기**: 한 크기(20px), 붐빌 때만 13px 까지 축소. 이웃이 멀다고 키우지 않는다.
- **홈 입력 3경로**: 「앨범에서」·「촬영」(기본, 2026-10-20 확정)·「붙여넣기」. 붙여넣기 버튼은 `clipboard.read()` 가능한 브라우저에서만 보이고, 데스크톱은 Ctrl/Cmd+V 도 받는다. 안내·오류 문구는 프레임 안 기존 문구 자리에 잠깐 띄워 화면을 더 가리지 않는다.
